# Сервис подписок

Сервис подписок - сервис, который позволяет пользователям отслеживать свои траты на онлайн-подписки. Пользователи могут оформить подписки на популярные сервисы (по аналогии с Яндекс Музыкой, Яндекс 360, Whoosh Pass), пополнить счет на сервисе и автоматически оплачивать подписки с этого счёта. Благодаря сервису пользователь сможет удобно рассчитать, на какие сервисы подписка еще нужна, а где уже перестала быть нужной, и отключать ненужные для экономии средств.

## Краткое описание предметной области

Сервис подписок позволяет пользователям управлять своими онлайн-подписками на различные сервисы. Основные сущности предметной области:
- Пользователь - человек, использующий сервис для управления своими подписками
- Подписка - запись об оформленной подписке на определенный сервис
- Сервис - онлайн-сервис, на который можно оформить подписку
- Платеж - операция по пополнению баланса или списанию средств за подписку

## Краткое обоснование целесообразности и актуальности проекта

Сервис подписок актуален в современном мире, где пользователи оформляют множество онлайн-подписок на различные сервисы. Часто люди забывают об автоматических продлениях и продолжают платить за неиспользуемые сервисы. Наш сервис поможет пользователям отслеживать все свои подписки в одном месте, контролировать расходы и легко управлять подписками.

## Краткое описание акторов (ролей)

- Пользователь: обычный пользователь системы, который может управлять своими подписками, пополнять баланс и просматривать статистику.
- Администратор: пользователь с расширенными правами, который может управлять всеми подписками, пользователями и просматривать общую статистику.

## Пользовательские сценарии

### Сценарий 1: Добавление новой подписки
1. Пользователь заходит в личный кабинет
2. Переходит в раздел "Мои подписки"
3. Нажимает кнопку "Добавить подписку"
4. Выбирает сервис из списка
5. Указывает параметры подписки (тип, срок)
6. Подтверждает добавление

### Сценарий 2: Пополнение баланса
1. Пользователь заходит в личный кабинет
2. Переходит в раздел "Баланс"
3. Нажимает кнопку "Пополнить"
4. Указывает сумму пополнения
5. Выбирает способ оплаты
6. Подтверждает операцию

### Сценарий 3: Просмотр статистики расходов
1. Пользователь заходит в личный кабинет
2. Переходит в раздел "Статистика"
3. Выбирает период для анализа
4. Просматривает графики и таблицы расходов
5. Анализирует, какие подписки наиболее затратные

## Лабораторная работа №2. Документирование архитектуры

### 1. Описание приложения с точки зрения взаимодействия с пользователем и выбранного стека

Приложение «Сервис подписок» предоставляет пользователям веб-интерфейс (SPA) и REST API для управления подписками на онлайн-сервисы. Пользователь может:
- Регистрироваться и аутентифицироваться.
- Просматривать список своих активных подписок.
- Добавлять новые подписки, указывая сервис, тип и срок.
- Применять промокоды для получения скидок.
- Пополнять баланс и отслеживать историю платежей.
- Анализировать статистику расходов с помощью графиков и отчётов.

**Выбранный технологический стек:**
- **Бэкенд**: Go (Golang) — высокопроизводительный язык, фреймворк Gorilla/mux для маршрутизации, pgx для работы с PostgreSQL.
- **Фронтенд** (планируется): TypeScript + Vue 3 — современный фреймворк для построения реактивных одностраничных приложений.
- **База данных**: PostgreSQL — хранение пользователей, подписок, промокодов, планов подписок, платежей.
- **Кэш и сессии**: Redis — хранение промокодов, сессий авторизации, временных данных.
- **Документация API**: OpenAPI (Swagger) — спецификация, по которой генерируется клиентский и серверный код (см. `doc.yaml`).
- **Контейнеризация**: Docker и Docker Compose для развёртывания всех компонентов.

### 4. Диаграмма базы данных

Система использует две СУБД: **PostgreSQL** для постоянного хранения основных сущностей и **Redis** для кэширования и сессий.

#### PostgreSQL
Основные таблицы и связи представлены на ER-диаграмме ниже.

![Диаграмма базы данных](readme_media/Diagram%201.png)

#### Redis
Используется для хранения:
- **Промокоды** (ключ: `promocode:{code}`, значение: JSON с полями промокода, TTL = время до истечения).
- **Сессии авторизации** (ключ: `session:{token}`, значение: user_id, TTL = 30 минут).
- **Кэш статистики** (ключ: `stats:{user_id}:{period}`, значение: агрегированные данные, TTL = 1 час).

### 5. Информация о языках программирования проекта

- **Бэкенд**: Go (версия 1.21+).  
  Используемые пакеты: gorilla/mux (маршрутизация), pgx (драйвер PostgreSQL), redis/go-redis (клиент Redis), logrus (логирование), oapi-codegen (генерация кода из OpenAPI).
- **Фронтенд** (планируется): TypeScript (версия 5+) с фреймворком Vue 3 (Composition API), сборка через Vite.
- **База данных**: SQL-скрипты для PostgreSQL (миграции находятся в папке `migrations/`).
- **Инфраструктура**: Docker, Docker Compose, Makefile для автоматизации.

Все зависимости задокументированы в `go.mod`, `package.json` (будет создан для фронтенда) и `docker-compose.yml`.
